# Production-Grade Annual Report Extraction Engine

## Scope: United States + United Kingdom, fiscal years 2017–2025

## Mission

Build a restart-safe, production-grade ingestion system that collects annual reports for a supplied universe of US and UK companies for fiscal years **2017 through 2025**.

Use exactly these two primary sources:

```text
USA → SEC EDGAR
UK  → FCA National Storage Mechanism (NSM)
```

The system must be optimized for:

```text
bulk metadata discovery
→ zero unnecessary searches
→ direct document URLs
→ asynchronous downloading
→ local SSD staging
→ automatic validation
→ SHA-256 deduplication
→ checkpointing
→ retry/resume
```

Do not browse company pages one by one.

Do not use Google search for ordinary discovery.

Do not launch browsers for ordinary downloading.

Do not discover and download serially.

The program should be able to crash, restart, and continue from exactly where it stopped.

# 7. Mandatory SEC headers

Every SEC request must identify the application.

Configure:

```python
SEC_HEADERS = {
    "User-Agent": "AnnualReportResearch your-real-email@example.com",
    "Accept-Encoding": "gzip, deflate",
}
```

Replace the email with the real operator contact.

SEC specifically requests a declared User-Agent for automated access. ([SEC][2])

# 8. SEC request-rate controller

Never exceed:

```text
10 requests / second total
```

across the application.

SEC's current Fair Access guidance specifies no more than 10 requests per second regardless of the number of machines being used. ([SEC][3])

Configure production target:

```text
8.5–9.0 requests/sec
```

Use a **global token bucket**.

Example conceptual configuration:

```python
SEC_RATE = 8.8
SEC_BURST = 2
SEC_MAX_CONNECTIONS = 24
```

Important:

```text
connections ≠ requests/sec
```

24 open keep-alive connections are acceptable internally, while the token bucket still permits only about 8.8 new requests each second.

The limiter must sit immediately before every SEC HTTP request.

# 9. SEC discovery phase

### Phase A — download bulk metadata once

At startup:

```text

```

If the cached copy is current enough for the run, reuse it.

Otherwise download once.

Then extract locally.

Do not make 10,000 individual Submissions API requests when the bulk dataset already exists.

SEC's entity JSON contains at least one year or 1,000 of the most recent filings; where more history exists, the JSON contains references to additional historical JSON files. ([SEC][1])

# 14. Build direct SEC Archive URL locally

No extra search request is required.

Given:

```text
CIK = 320193

accessionNumber =
0000320193-24-000123

primaryDocument =
aapl-20240928.htm
```

calculate:

```python
cik_path = str(int(cik))

accession_path = accession_number.replace("-", "")

url = (
    "https://www.sec.gov/Archives/edgar/data/"
    f"{cik_path}/{accession_path}/{primary_document}"
)
```

SEC documents that accepted filings live under the CIK and accession-number directory structure, with the accession dashes removed in that directory. ([SEC][2])

Result pattern:

```text
https://www.sec.gov/Archives/edgar/data/
{CIK}/
{ACCESSION_WITHOUT_DASHES}/
{PRIMARY_DOCUMENT}
```

This URL should be generated locally for thousands of rows in milliseconds.

# 23. FCA discovery by date shards

For 2017–2025, divide the initial discovery by date.

Conceptually:

```text
2017-01-01 → 2017-12-31
2018-01-01 → 2018-12-31
...
2025-01-01 → 2025-12-31
```

Use the endpoint's date criterion.

The government-published example shows a `publication_date` date criterion in the request body. ([contractsfinder.service.gov.uk][4])

Pattern:

```json
{
  "from": 0,
  "size": 2000,
  "sort": "publication_date",
  "keyword": null,
  "sortorder": "asc",
  "criteriaObj": {
    "criteria": [],
    "dateCriteria": [
      {
        "name": "publication_date",
        "value": {
          "from": "2024-01-01T00:00:00Z",
          "to": "2024-12-31T23:59:59Z"
        }
      }
    ]
  }
}
```

If the current API schema uses a slightly different casing or envelope, inspect one successful current NSM browser request and update only the FCA adapter.

Do not redesign the pipeline.

Unlike SEC, do not hard-code an invented public request-per-second limit.

Use adaptive concurrency.

Initial:

```text

```

After a stable warm-up:

```text
8
```

Potential maximum:

```text
16
```

only when:

```text

low error rate
stable latency

```

Implement additive increase / multiplicative decrease:

```text

repeated 503
→ concurrency × 0.5
```

```text

```

Maximum configured:






# 36. Hash every object

Calculate:

```text
SHA-256
```

during streaming if possible.

Do not reread a multi-megabyte file unnecessarily.

Pseudo-flow:

```python
sha = hashlib.sha256()

while chunk:
    file.write(chunk)
    sha.update(chunk)

digest = sha.hexdigest()
```

Create a database index on:

```text
sha256
```

If hash already exists:

```text
DUPLICATE
```

Keep the new source URL as provenance even if only one physical file is retained.

# 41. Database writes

SQLite:

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
PRAGMA temp_store=MEMORY;
```

Do not commit separately after every 50 KB network chunk.

Batch metadata updates.

For example:

```text
commit every 50–200 completed records
```

except status transitions required for crash safety.

---

# 42. Priority scheduler

Order jobs roughly by:

```text
priority 1
small known direct objects

priority 2
normal direct documents

priority 3
large documents

priority 4
fallback/resolution tasks
```

For a live demonstration, process known direct documents first so throughput becomes visible immediately.

Production completeness must eventually process every queue item.

---

# 43. Do not HEAD every file automatically

A common performance mistake is:

```text
HEAD
↓
GET
```

which doubles network requests.

Prefer:

```text
GET with streaming
```

and inspect the returned headers.

Use HEAD only when there is a specific reason.

This is especially important for SEC because every request consumes part of the request-rate budget.

---

# 44. Keep connections alive

Never create a new HTTP client for every document.

Create:

```text
one SEC AsyncClient
one FCA AsyncClient
```

and keep them alive for the entire run.

Benefit:

```text
fewer TCP handshakes
fewer TLS handshakes
lower latency
higher throughput
```

---

# 45. Compression

For metadata:

```text
Accept-Encoding:
gzip, deflate
```

For already-compressed PDF/ZIP documents, compression normally provides little benefit.

Do not decompress network data into RAM unnecessarily.

## 50. One report per fiscal year

```text
company_id
+
report_year
+
report_type
```

For the main annual report:

```text
report_type = AR
```

```text
canonical
amendment
duplicate
corrected
alternative format
```

must be explicit.

# 51. Never invent missing reports

If no report can be verified:

```text
NOT_FOUND
```

Do not:

```text
guess URL
guess year
copy adjacent year
invent document identifier
```

# 52. Preserve provenance

Every physical report must remain traceable to:

```text
country
source
company
CIK/LEI
report year
filing/publication date
accession/document identifier
original URL
retrieval timestamp
SHA-256
```

A final PDF without provenance is incomplete data.

# PART IX — FAILURE RECOVERY

## 53. Internet dies

Do nothing special.

When connectivity returns:

```text
RETRY queue resumes
```

---

# 54. PC crashes

At restart:

```text
DOWNLOADING → RETRY
```

Existing valid final files remain untouched.

`.part` files may either:

```text
resume if supported
```

or:

```text
delete and restart
```

depending on server Range support.

---

# 55. Rate limiting

SEC:

```text
never raise the configured request rate above the permitted ceiling
```

FCA:

```text
reduce concurrency automatically
```

Never respond to throttling by opening more machines, more proxies, or rotating IPs.

---

# 56. Duplicate reports

If:

```text
SHA256 A == SHA256 B
```

do not waste storage.

Maintain both database source records pointing to the same canonical physical object.

# PART XI — PERFORMANCE TARGETS

```text

effectively instantaneous for normal datasets

adaptive parallel downloading based on observed server behavior

VALIDATION:
multiple files simultaneously

HASHING:
performed while streaming whenever possible

batched writes

local SSD
```

```text
MB/sec

failure rate

completeness
```
